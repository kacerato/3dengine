02

ARQUITETURA OBSERVADA

DO PAINEL VISUAL
ATÉ A EXECUÇÃO.

O NoCode não é apenas uma tela. O painel abre um canvas, liga um executor ou um arquivo de grafo e o runtime entra em ação quando o projeto é executado.

EDITORActivities / Panels / NoCode
CANVASgrafo visual, nós e conexões
EXECUTORNoCodeExecutor ou graphFile
RUNTIMEJAVARuntime + APIs internas
PLAYobjetos, input, física e render
Detalhe importante: o painel suporta dois contextos: um NoCodeExecutor ligado a um componente do GameObject e um graphFile carregado como “NoCode Graph”. A documentação diferencia os dois fluxos.

08

MODELO MENTAL

O QUE ACONTECE
QUANDO VOCÊ DÁ PLAY.

Esta sequência é a forma recomendada de ler os arquivos quando estiver rastreando por que um grafo ou ação funciona — ou não funciona.

1. GRAPHo painel aponta para executor ou arquivo
2. NODESdados e branches formam o fluxo
3. RUNTIMEações são resolvidas para APIs reais
4. ENGINEcomponentes, objeto, input e física
5. FRAMEresultado aparece em execução
Para depurar uma mecânica, comece no nome do nó, confirme o tipo dos pinos, procure a ação correspondente no runtime e só depois desça para a implementação do componente de engine.

TRANSPARÊNCIA DA AUDITORIA

DECOMPILADO NÃO É
CÓDIGO-FONTE ORIGINAL.

Nomes ofuscados, divisão entre dex e classes ausentes podem impedir reconstruir uma API apenas pelo Smali. A documentação marca a origem para evitar falsa precisão.

FONTE DIRETA

Informação visível no dump, como caminhos, classes, strings, temas e chamadas explícitas.

CATÁLOGO CORRELACIONADO

Para os nomes e contratos dos NoCodes, o catálogo oficial da ITsMagic é usado como índice correlacionado e os detalhes são carregados da própria documentação oficial.

NÃO CONFIRMADO

Quando uma classe referenciada pelo Smali não está presente na árvore versionada, a documentação não inventa os métodos internos.

ATUALIZAÇÃO AUTOMÁTICA

A Referência do Dump consulta a árvore atual do repositório para reduzir divergência quando novos arquivos forem adicionados.
